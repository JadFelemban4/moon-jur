# CLAUDE.md — مشروع رحلة إلى القمر (Moon Journey VR)

تعليمات دائمة لأي جلسة Claude تشتغل على هذا المشروع. اقرأ `BRIEF.md` للفكرة، و`Context.md` للبنية التقنية، و`handoff.md` لآخر حالة.

## الملفات

- **`MOON-JOURNEY-02-VR.html`** — ملف الإنتاج الوحيد. كل شي جواه (JS + نماذج GLB مضمنة base64، ~6.8MB). ما فيه build ولا dependencies خارجية غير Three.js r128 من cdnjs.
- `source/asset/` — صندوق وارد لملفات خام (GLB من Blender وغيره) قبل المعالجة. النماذج الحالية من المستخدم (SLS + أجزاؤه، Orion، لاندر وأرضية سطح القمر) مضمنة كلها base64؛ ملفات `.blend/.blend1` هنا ملفات عمل Blender — تجاهلها. **`Cockpit.glb` (25MB) لسا متتبّع بالمستودع رغم إنه غير مستخدم بالكود — مرشح للحذف، اسأل المستخدم أولاً.**
- `source/audio_tracks/*.mp3` — 15 مقطع سرد صوتي (`{stage}.{card}.mp3`) لبطاقات التعليمات، **ملفات منفصلة غير مضمنة** بالـ HTML (يُحمّلون بمسار نسبي `source/audio_tracks/...` وقت التشغيل — راجع Context.md).
- `claude/` — هذي التوثيقات. **حدّثها في نهاية كل جلسة عمل** (خصوصاً handoff.md).
- `.superpowers/` / `.codex/` — ملفات جلسات وكلاء (عصف ذهني مرئي / Codex)، متجاهلة بـ `.gitignore`.
- **المستودع على GitHub**: https://github.com/JadFelemban4/moon-jur.git (فرع `main`) — منقول من مجلد محلي بدون git يوم 2026-07-13. مربوط بـ Vercel للنشر التلقائي (راجع قسم النشر تحت).

## قواعد عمل ملزمة

1. **التجربة VR-only** — لا ترجّع أي UI للديسكتوب/الجوال (welcome screens، joystick، mouse-look، DOM overlays) **في ملف الإنتاج**. كل الواجهة داخل المشهد: لوحة المعصم الأيسر + toast أمام الرأس. (ملاحظة 2026-07-08: قرر المستخدم أن التجارب *القادمة* يكون معها ملف اختبار ديسكتوب منفصل بأزرار تخطي مراحل — راجع القالب العام. لو طلب نفس الشي لهذا المشروع، يكون ملف dev منفصل ولا يلمس ملف الإنتاج.)
2. **الدفع لـ GitHub صار جزء عادي من سير النشر** (تحديث 2026-07-13 — المشروع صار على GitHub وأي `push` لفرع `main` ينشر تلقائياً على Vercel). رغم هذا: **اطلب تأكيد صريح قبل أي `git push`** لأي تغيير — نفس مبدأ الحذر العام، فقط الحاجة لطلب إذن "افتح remote جديد" انتفت لأنه موجود أصلاً.
3. **قبل أي نشر:** فحص syntax إلزامي:
   ```bash
   node -e "const fs=require('fs');const html=fs.readFileSync('MOON-JOURNEY-02-VR.html','utf8');const s=[...html.matchAll(/<script(?![^>]*src)[^>]*>([\s\S]*?)<\/script>/g)].map(m=>m[1]);s.forEach((x,i)=>{try{new Function(x);console.log(i,'OK')}catch(e){console.log(i,'ERR:',e.message)}})"
   ```
4. **النشر على Vercel — الطريقة الحالية (2026-07-13+): عبر git، لا يدوي.**
   - عدّل → افحص syntax → `git add` → `git commit` → (تأكيد المستخدم) → `git push origin main` → Vercel ينشر تلقائياً خلال ثوانٍ (ربط GitHub Integration).
   - **`vercel.json` بجذر المشروع يعيد توجيه `/` إلى `/MOON-JOURNEY-02-VR.html`** — ضروري لأن اسم الملف مو `index.html` والنشر عبر git يرفع بنية المستودع كما هي (لا تحذف هذا الملف، ولا تغيّر اسم `MOON-JOURNEY-02-VR.html` بدون تحديث الـ rewrite).
   - الرابط الثابت للاختبار: **https://moon-vr-deploy.vercel.app**
   - **طريقة النشر اليدوي القديمة (نسخ لملف scratchpad + `vercel deploy --yes --prod`) صارت متروكة** — كانت تُستخدم قبل ربط GitHub، خلّت الموقع يعمل من نسخة معزولة بدون `source/` (لذلك الصوتيات ما كانت تصل). لا تستخدمها إلا لو انقطع ربط GitHub لسبب ما.
   - Deployment Protection **معطّلة عمداً** — لا تعيد تفعيلها؛ النظارة تحتاج رابط عام بدون تسجيل دخول (جدار SSO كان سبب `NotSupportedError` استغرق تشخيصه طويلاً).
   - **بعد كل push:** تحقق فعلياً `curl -o /dev/null -w "%{http_code}" https://moon-vr-deploy.vercel.app/` = 200 (النشر التلقائي يأخذ ~15-30 ثانية) — لا تكتفِ بنجاح الـ push.
5. **المستخدم هو المختبِر** — ما عندك نظارة. بعد كل نشر اطلب منه يجرب على Quest 3 وقل له بالضبط وش يتحقق منه. لا تدّعي أن شي "يشتغل" قبل ما يؤكده.
6. **المحتوى ثنائي اللغة** (عربي/إنجليزي عبر `language.t()` و`DICT`) — أي نص جديد يجي بالنسختين. **استثناء حالي**: سرد بطاقات التعليمات الصوتي (`source/audio_tracks/`) عربي فقط لحد الآن (ElevenLabs، voice ID `C1npRmjB19a6yNkEucvx`، قد يتغيّر) — يشتغل بنفس الصوت حتى لو الواجهة إنجليزي. تفاصيل الفجوة والخطوات لإكمالها في `handoff.md`.
7. **لا تغيّر مفاتيح التعلم** (`s1_*` … `s5_*`، procedure keys، quiz) بدون سبب — مربوطة بـ xAPI وحالة التقدم والشهادة.

## دروس VR مدفوعة الثمن — لا تكررها

- **الـ rig على الأرض:** مع `local-floor` طول المستخدم الحقيقي **يُضاف** فوق `app.player.position.y`. أي مشهد room-scale لازم `player.y = 0` (خطأ y=1.3 خلّى عيون المستخدم عند السقف — شكوى "كل شي في دائرة والكاميرا من فوق").
- **لا تلمس دوران/موضع الكاميرا في VR** — النظارة تملكه. حرّك `app.player` (rig). لتوجيه اللاعب عند دخول مشهد: `snapPlayerYaw(target)` مرة واحدة فقط، أبداً ليس كل فريم (يسبب دوار).
- **Render-to-texture أثناء جلسة XR:** عطّل `renderer.xr.enabled` مؤقتاً وقت رسم الـ RT بكاميرا خاصة ثم رجّعه (مطبق في ground cam بمشهد S2).
- **الأزرار ثلاثية الأبعاد:** استخدم `app.actionTargets` مع `userData.onAction` — تنفحص أول شي في `handleRaycastHit`، وتتصفّر تلقائياً في `freshScene()`.
- **الأصول الكبيرة:** أي ملف جديد >2MB يُنشر كملف منفصل جنب index.html، لا base64 (درس Cockpit.glb الـ 25MB — والـ atob على نص 34MB يخنق متصفح Quest).
- **GLB من Blender بدون تصفير transforms** يحمل إزاحات المشهد الأصلي وقد يختلف حجمه المحمّل عن حدود الهيدر — **أعد التمركز وقِس بـ Box3 وقت التشغيل** قبل أي وضع/تحجيم (درس تداخل رقع S5 ونموذج SLS 50→86).
- **مواد GLB البيضاء:** أصلحها بالاسم في `MAT_TINTS` بدل تعديل ملفات المستخدم.
- **قبل ضبط مناطق تفاعل على نموذج جديد:** صوّره فعلياً (viewer + Playwright، الوصفة في Context.md) وقِس بالنسب المئوية — لا تخمّن التشريح.
