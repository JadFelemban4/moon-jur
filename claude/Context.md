# Context — البنية التقنية

كل الكود في ملف واحد: `MOON-JOURNEY-02-VR.html` (~6.5MB، ~5400 سطر منطق + نماذج base64). Three.js **r128** من cdnjs + GLTFLoader مضمّن يدوياً في أول الملف.

## الأنظمة الرئيسية (بترتيب وجودها في الملف)

| النظام | الوصف |
|--------|-------|
| `GLTFLoader` مضمّن | نسخة r128 كاملة داخل IIFE |
| `language` / `DICT` | ثنائية اللغة ar/en، `language.t(key)`، `language.toggle()` |
| `xapi` | تسجيل أحداث تعلم (initialized/discovered/…) |
| `sm` (state machine) | حالة المراحل: `stageDef/stageState/markDiscovery/performStep/nextLesson/answerQuiz/advance/canAdvance` — **`markDiscovery` يرفض قبل إتمام الدرس (locked)** |
| `audio` | أصوات مولدة (click/chime/error/success/boom/countdown/rumble + ambient) |
| `MDL_*` base64 | النماذج المضمنة: `MDL_SLS/SRBL/SRBR/LAS/CORE/ICPS/ORION` (عتاد حديث من المستخدم) + `MDL_LANDER/MOONFLOOR` (سطح القمر) + `MDL_PAD39B` (بيئة منصة الإطلاق، **مقياس واقعي 1:1** — 420×105×420م) + `MDL_MOON` (LRO). تُفك في `loadModels()` → `MODELS.*` |
| `MAT_TINTS` / `applyMatTints` | إصلاح ألوان مواد بالاسم بعد التحميل (`Mat_Mare`/`Mat_Lunar_Floor`/`Mat_LM_Gold_Foil`/`Mat_Dark_Nozzle`) — ملفات GLB الأصلية تُركت كما سلّمها المستخدم. **و`Mat_Invisible_Trigger` يُجعل شفافاً بالكود** (opacity 0 + transparent) لأن `visible=false` كان سيعطّل الـ raycast على التريغرات |
| `app` | الحالة العامة: renderer، camera، **player (rig)**، controllers، raycaster، anim[]، stepTargets[]، **actionTargets[]**، hud{} |
| `initGL()` | renderer + rig + كنترولرز (ray+tip) + `initHudPanels()` + `addVRButton()` |
| `addVRButton()` | زر ENTER VR: معطل حتى `loadModels` يخلص، يطلب الجلسة، وأول دخول ناجح يستدعي `start()`. فيه `runDiagnostics()` يعرض تشخيص WebXR كامل على الشاشة عند أي فشل |
| لوحة المعصم | إحداثيات منطقية 512×400 لكن الكانفس يرسم بدقة مضاعفة (1024×800 مع `ctx.scale(2,2)` — لا تغيّر الإحداثيات المنطقية، الوضوح يجي من دقة التكستشر) → `CanvasTexture` على plane 0.21×0.164م بيد **يسرى** (تُكشف بـ handedness من حدث `connected`). أوضاع: stage/lesson/quiz/cert عبر `app.hud.mode`، أزرار عبر `hitRects` + UV (بالإحداثيات المنطقية)، و`app.hud.blocking` يمنع التفاعل مع المشهد وقت الدرس/الاختبار |
| toast | canvas 512×128 على plane ابن الكاميرا، يختفي بعد 2.8s |
| `handleRaycastHit()` | ترتيب الفحص: **actionTargets ← stepTargets (procedure) ← interactables (discoveries)** |
| `snapPlayerYaw(target)` | يلف الـ rig مرة واحدة ليتطابق اتجاه نظر اللاعب الفعلي مع اتجاه المشهد — يُستدعى عند دخول كل مشهد فقط |
| `freshScene(bg)` | يبني scene جديدة: يصفّر anim/stepTargets/actionTargets/liveStat، يضيف إضاءة افتراضية + نجوم، **ويعيد ربط `app.player` بالمشهد الجديد** |
| `SCENE_BUILDERS[0..4]` | المشاهد الخمسة s1–s5 |
| `tick()` | حلقة الرسم: anim callbacks + baseLookTarget (ديسكتوب فقط، معطل وقت `xr.isPresenting`) + render |

## نقاط دقيقة يسهل كسرها

- **`app.player.position.y = 0` في المشاهد الداخلية** (S2) — طول الرأس الحقيقي يُضاف فوقه مع local-floor. المشاهد الخارجية (S3/S4) مرفوعة عمداً (منصة مشاهدة). S5 بارتفاع عين واقعي 1.7م. **S1 رجعت لمنظور مرتفع "طائر" (y=80)** بعد فيدباك المستخدم (2026-07-14) — نفس إحداثيات x/z المضبوطة سابقاً (رؤية الصاروخ+البرج بدون تحجّب)، بس الارتفاع فقط تغيّر من 1.7 إلى 80 مع خفض ارتفاع نقطة النظر من 55 إلى 35 (زاوية نظر هابطة معتدلة). فكرة هليكوبتر متحرك مذكورة كطلب مستقبلي محتمل، غير منفذة.
- كل teleport بين المشاهد: `app.player.position.set(...)` + `app.camera.position.set(0,0,0)` + `snapPlayerYaw(...)`.
- **S2 يشيل إضاءة `freshScene` الافتراضية** ويستبدلها بإضاءة معتمة (ambient خافت + point دافئ + cyan fill) — لا تضيف إضاءة عامة له.
- **GROUND CAM** (S2): `WebGLRenderTarget` 256² + كاميرا `downCam` تحت الكبسولة تصوّر `earthG` — التقنية: عطّل `renderer.xr.enabled` → `setRenderTarget(camRT)` → render → رجّع كل شي. طبقة HUD نصية شفافة فوق الشاشة.
- **`updateEarth(alt)`** (S2): الأرض كرة R=180 تبدأ تحت الكبسولة وتبتعد `dist = R + alt^1.6 × 1.1` مع lerp لاتجاه أمامي-سفلي (gravity turn) — النهاية كوكب كامل في الزجاج. الـ sky dome كبيرة (2600) عشان الأرض تبقى جواها.
- **S4 المهام**: متغير `task` (1 مسافة → 2 تصحيح → 3 كبح → 4 مدار). السرعة `dt*0.042`. نافذة الكبح `travel ∈ [0.84, 0.92]` — نقاطها تتلون **أحمر** (أحمر = مكابح، ونصوص التوجيه تقول "النقاط الحمراء" — غيّر الاثنين معاً لو عدّلت اللون). فوات القمر عند 0.97 → إعادة من 0.62. **`award()` لازم يُستدعى قبل تقدم المهمة** (يفشل locked لو الدرس ما خلص). دفعة التصحيح: لهب `startCorrectionBurn()` والمكوك يثبت مكانه ويرتفع حتى `drift=0` ثم `task=3`.
- الكونسول في S2 ينسحب تحت الأرض بعد إتمام الخطوات (anim ينزل `consoleG` ثم يصفّر `stepTargets`).
- **أحداث الانفصال في S2** (`jettison()` داخل s2): بعد طبقة index 1 (ستراتو) ينفصل المعززان، بعد index 3 (ثيرمو) برج الهروب، وعند المدار المرحلة الأساسية — الـ toast مؤجل ~3s حتى لا يطمس toast الاكتشاف (لوحة toast واحدة).
- **مناطق S1** مضبوطة بالنسب المئوية من ارتفاع الصاروخ (مقاسة أصلاً من لقطة شاشة فعلية): محركات 0–7%، مرحلة أساسية 8–67%، معززان أسطوانتان عند x=±0.75×SCALE من 0.5–63%، القسم العلوي 69–100%. **الأنصاف مضبوطة بحيث لا تتقاطع الأسطوانات أبداً** — أي تداخل هندسي بين colliders يخلي الراي يصيب "المنطقة الغلط" (حصلت وانصلحت). `bandCyl()` مرتين لنفس المفتاح آمن (تكرار الليبل يمنعه `_labeledKeys`).
- **S1 أعيد بناؤه بمقياس واقعي 1:1** (2026-07-14): بيئة `MODELS.pad39b` (LC-39B-style: hardstand، تريتش، برج حقيقي، خزان ماء، crawlerway، مستنقع وأشجار — 420×105×420م) حلّت محل الأرضية/المنصة/البرج الابتدائي. الصاروخ يرتفع الآن H=98 (بدل 11 بالديوراما القديمة) — **كل شي متعلق بأبعاد الصاروخ (مناطق الاكتشاف، نصف قطر حلقة التمييز) مضروب بـ`SCALE = H/11 ≈ 8.909`** حتى تبقى النسب اللي انضبطت بالديوراما صحيحة بالمقياس الجديد. الكاميرا الآن بارتفاع عين واقعي (1.7م) بدل الارتفاع المرتفع القديم (كان منطقياً بس بمقياس اللعبة الصغير) — المسافة/الزاوية اختيرت افتراضياً بدون اختبار حقيقي على النظارة، **ينتظر تأكيد المستخدم**. `PAD_Y=0.7` تطابق موضع node اسمه `Pad_Hardstand` بالنموذج.
- **`pulse()` فيها حارس `_pulsing`** — بدونه الضغط المتكرر وسط النبضة يلتقط الحجم المتضخم كأساس ويكبر الأوبجكت/الليبل تدريجياً مع كل ضغطة (باغ حقيقي انصلح).
- **`hudButton` يعمل `ctx.save()/restore()`** — أي دالة رسم مشتركة على كانفس اللوحة لازم تحفظ/ترجع حالة الـ ctx؛ تسريب `textAlign='center'` منها كان يقصّ بدايات كل سطور اللوحة (باغ حقيقي انصلح 2026-07-08). الهامش الداخلي padX=34 وعرض اللف HUD_W−68.
- **نافذة S2 دائرية** (porthole): bulkhead `RingGeometry(0.85, 3.4)` + إطار torus + حلقة توهج + 8 براغي، بنفس موضع/ميلان الإطار القديم (0, 1.62, −1.55 / rot.x −0.42).
- **S5**: أرضية `MODELS.moonfloor` وحدة (أوفستها صفر — ما تحتاج recenter)، الاكتشافات على أوبجكتات `Trigger_Crater/Mare/Regolith` بالاسم، مواقع الجولة الموجهة تُقرأ ديناميكياً من مواضع التريغرات (لو تحركت في Blender الجولة تتبعها)، واللاندر على منطقة الهبوط عند (0,0).
- **S5 مكبّرة ×4 (2026-07-14)**: `floor.scale.setScalar(4)` (36م → 144م) — الجولة الموجهة تتكيّف تلقائياً (تقرأ `getWorldPosition()` حيّة، ما تحتاج تعديل يدوي على الإحداثيات). أضيفت أرضية قمرية كبيرة إضافية (`PlaneGeometry(900,900)` بتموّج خفيف، y=-0.15) تحت/حول الرقعة المنحوتة كامتداد أفق — الرقعتان مستقلتان بتموّجهما، **احتمال درزة بصرية عند الحافة (144م) غير مؤكد على النظارة بعد**. اللاندر بقي بدون تحجيم عند (0,0,0) بافتراض إن منطقة الهبوط المسطحة بالنموذج تمر من أصل محلي y=0 (لم يُتحقق بصرياً). الكاميرا 1.7م ارتفاع، `(0,1.7,25)` تنظر لـ`(0,1.5,-15)`، `setWalkable(true,70)`.
- **S5 ألوان الفوهة/البحر/الريغوليث (2026-07-14)**: `MODELS.moonfloor` (النموذج المنحوت الواحد، بعد دمج جلسة 2026-07-08) يحمل بس مادتين عامتين (`Mat_Lunar_Floor`, `Mat_Moon_Rock`) — **لا مادة خاصة لكل ميزة**، فُقد التمايز اللوني اللي كان موجود بالنماذج المنفصلة القديمة (تحقق بفك ترويسة glTF JSON من الـbase64 مباشرة، نفس طريقة فحص GLB الموثقة بالأسفل). الحل بالكود بدل لمس ملف المستخدم: `groundPatch(x,z,radius,hex,opacity)` — دائرة `CircleGeometry` بنسيج `radialTex()` (canvas تدرّج شعاعي شفاف الحواف) توضع عند موضع كل `Trigger_*` الحي (نفس `wp` المستخدم بمصفوفة `tour`). الألوان: فوهة `0x16181c` غامق جداً r=10، بحر `0x3f4652` (نفس Mat_Mare القديم) r=16، ريغوليث `0xcdb99a` بيج فاتح r=10. **لو أعاد المستخدم تصدير النموذج بمواد مسمّاة `Mat_Crater/Mat_Mare/Mat_Regolith`، حوّل لـ`MAT_TINTS` بدل الرقع اليدوية** (نفس نمط الحل الصحيح المفضّل بالمشروع).
- **إزاحات GLB الداخلية**: رقع سطح القمر (وأي GLB من Blender بدون تصفير transforms) تحمل مواضع مشهد Blender — `placePatch()` في s5 يعيد التمركز من Box3 قبل الوضع. **حجم النموذج المحمّل ≠ حدود accessors** (نموذج SLS: 50 وحدة في الهيدر لكن 86.25 محمّلاً بسبب node scales) — قِس دايماً بـ Box3 وقت التشغيل.
- `labelPlate(text,w,h,bg,fg)` لوحات نص قابلة للضغط، فيها `userData.repaint(color)` لإعادة الرسم بعلامة ✓.
- **أدوات معاينة النماذج**: viewer.html + shot.js (Playwright headless + سيرفر محلي + مسطرة نسب مئوية) — كانت في scratchpad الجلسة `sls-viewer/`؛ أعد بناءها عند الحاجة: صفحة تحمّل GLB وتصوّره بكاميرا front/angle مع خطوط كل 10% من الارتفاع.

## النشر (أعيد تصميمها 2026-07-13)

- **المستودع**: https://github.com/JadFelemban4/moon-jur.git، فرع `main` — منقول لـ git بعد ما كان محلي بدون تتبع. مربوط بـ Vercel Git Integration (alias `moon-vr-deploy-git-main-...` يؤكد الربط).
- **النشر تلقائي**: أي `git push origin main` يطلق نشراً جديداً خلال ~15-30 ثانية، بدون أي أمر Vercel يدوي.
- **`vercel.json` بجذر المشروع ضروري**: النشر عبر git يرفع بنية المستودع كما هي (لا نسخة معزولة بـ `index.html`)، واسم ملف الإنتاج `MOON-JOURNEY-02-VR.html` مو `index.html` — بدون الـ rewrite، `/` يرجع 404 (هذا بالضبط اللي صار يوم 2026-07-13 لما اتصل GitHub لأول مرة، قبل ما نضيف الملف).
  ```json
  { "rewrites": [ { "source": "/", "destination": "/MOON-JOURNEY-02-VR.html" } ] }
  ```
- **فائدة جانبية مهمة**: بما إن النشر يرفع كامل بنية المستودع، أي مسار نسبي داخل الكود (زي `source/audio_tracks/1.1.mp3`) يشتغل صح تلقائياً — ما نحتاج نعتني بنسخ ملفات مساعدة لمجلد النشر يدوياً زي قبل.
- الرابط الثابت (ثابت، ما يتغيّر بين النشرات): https://moon-vr-deploy.vercel.app — عام بدون حماية (Deployment Protection معطّلة عمداً، مطلوب للنظارة).
- **طريقة يدوية بديلة (متروكة، للطوارئ فقط)**: `vercel deploy --yes --prod` من مجلد staging فيه نسخة `index.html` + `.vercel/project.json` مربوط بنفس المشروع — هذي كانت الطريقة الوحيدة قبل ربط git، بس تنشر نسخة معزولة (بدون `source/`)، فأي مسار نسبي يعتمد على ملفات خارج الـ HTML (زي الصوتيات) ينكسر معها. استخدمها بس لو تعطّل ربط GitHub.
- **تحقق دايماً بعد push**: `curl -o /dev/null -w "%{http_code}" https://moon-vr-deploy.vercel.app/` = 200، مو بس نجاح أمر git.

## بيئة اختبار الكمبيوتر (source/pc_test/, أُضيفت 2026-07-14)

نسخة مستقلة من ملف الإنتاج لاختبار سريع بدون نظارة — نفس نمط `Al-amad_lab/source/شغّل_المختبر.bat` من القالب العام.

- **`pc_test/index.html`**: نسخة كاملة من `MOON-JOURNEY-02-VR.html` مع طبقة إضافية ملحقة آخر ملف (IIFE واحدة قبل `</script>`) — **لا تُنسخ هذي الطبقة أبداً لملف الإنتاج**.
- **ما تضيفه الطبقة**:
  - **mouse-look**: Pointer Lock API يحدّث `app.lookYaw`/`app.lookPitch` مباشرة من `mousemove`.
  - **WASD**: حركة مستقلة عبر `requestAnimationFrame` خاص (**مو** `app.anim` لأنه يتصفّر مع كل `freshScene()`)، تحترم `app.walkable`/`app.walkBounds` الحاليين للمشهد. **مُتحقّق فعلياً عبر Playwright** (تتبّع `app.player.position` مباشرة أثناء محاكاة ضغط مفاتيح حقيقية) — مو افتراض.
  - **كليك للتفاعل**: أول كليك يفعّل قفل الفأرة، بعدها كل كليك يرمي شعاع من نص الشاشة (crosshair). **لازم يكون التسجيل جوا `DOMContentLoaded` مو أعلى الـIIFE** — `app.renderer` يبقى `null` لحد `initGL()` (تشتغل بمستمع DOMContentLoaded الأصلي)، وأي مرجع فوري لـ`app.renderer.domElement` خارج ذلك يرمي خطأ يوقف تنفيذ باقي الـIIFE بصمت — **هذا بالضبط الباغ اللي خلّى لوحة الاختبار كلها ما تظهر أول مرة** (انصلح).
  - **لوحة المعصم مثبّتة على الكاميرا يدوياً** (زاوية سفلى-يمنى).
  - **لوحة تخطي مراحل** (أعلى يسار الشاشة): 5 أزرار، `sm._forceComplete(i)` + `sm._setStage(n)` (test helpers، `_forceComplete` من جلسة Codex، `_setStage` أضفتها أنا بنفس النمط — موجودة بملف الإنتاج أيضاً، خاملة بدون تأثير).
- **بنية السيرفر (مهمة، أُعيد تصميمها بعد باغ حقيقي)**: `dev_server_pc_test.py` يعيش بـ**`source/`** (مو داخل `pc_test/`) ويُشغَّل بـCWD=`source/`، عشان يقدر يوصل لمجلدي `pc_test/` و`audio_tracks/` مع بعض (إخوة، مو أحدهما جوا الثاني). بايثون `http.server` **ما يقدر يخرج فوق جذره أبداً** بأي `../` — لو السيرفر رايح داخل `pc_test/` نفسها، ما فيه طريقة يوصل لصوتيات `source/audio_tracks/` بتاتاً، بغض النظر عن basePath. الرابط صار `http://localhost:8643/pc_test/index.html` (مو `/index.html`)، والصوتيات `http://localhost:8643/audio_tracks/...` — و`createLessonNarration`'s `basePath` بملف `pc_test/index.html` مضبوط `../audio_tracks` (نسبي لموقع الملف الفعلي، يطابق الآن).
- **التشغيل**: `pc_test/شغّل_اختبار_بدون_نظارة.bat` يعمل `cd` لـ`source/` ثم يشغّل `dev_server_pc_test.py` (منفذ **8643** — مختلف عن منفذ Al-Amad 8642) ثم يفتح المتصفح على الرابط الصحيح تلقائياً. **لازم من خلال السيرفر** — فتح `index.html` مباشرة (`file://`) ما يشتغل.
- **المزامنة مع ملف الإنتاج**: نسخة يدوية — أي تعديل على `MOON-JOURNEY-02-VR.html` **ما ينعكس تلقائياً** على `pc_test/index.html`. لو المستخدم طلب اختبار تعديل جديد، انسخ ملف الإنتاج المحدّث فوق `pc_test/index.html` **ثم أعد إلحاق طبقة الاختبار** (نسخة احتياطية من الطبقة، انسخ الإنتاج الجديد، ألحق الطبقة من جديد — وتأكد `basePath` النسبي للصوتيات لسا `../audio_tracks`).
- **حجم الملف**: نسخة كاملة (~7MB) — **لم يُقرَّر بعد إذا يُرفع لـ git أو يبقى محلي فقط** — اسأل المستخدم.
- **منهجية التحقق المستخدمة (يستحق التكرار لأي دي باغ ثاني بهذا الملف)**: بدل تخمين سبب "الشي فلان ما يشتغل"، استخدم Playwright headless: افتح الصفحة، احقن `window.__appRef = app;` عبر `<script>` جديد (يشتغل لأن `app` const أعلى مستوى بنفس نطاق السكربت الكلاسيكي — لكن أي متغير معرّف **جوا IIFE أنا كتبتها** مثل `keys` ما يوصله حقن خارجي، لازم أضيف hook مؤقت داخل نفس الـIIFE وأشيله بعد). حرّك بمفاتيح حقيقية (`page.keyboard.down/up`)، اقرأ `app.player.position` قبل/بعد، قارن أرقام حقيقية — هذا اللي كشف باقي المسافة (220) بينما `walkBounds` كان (130) رغم كل شي ثاني يبدو صحيح ظاهرياً.
